## 设计

- 采用独立 CLIProxyAPI 服务 + ModelBridge 管理与透明代理。相比复制 Go 转换器到 Node.js，直接使用官方发布程序可以持续复用上游修复；相比只跳转第三方管理页面，自有界面仍统一负责状态、账号登录入口、模型目录、接入信息和验证记录。
- 复用已安装、已授权的本机 8317 服务。首次部署可以从界面绑定其他本机 CLIProxyAPI 实例；连接密钥由 ModelBridge 使用 DPAPI 加密保存。账号令牌仍由 CLIProxyAPI 原生存储管理，ModelBridge 不导入会员令牌。
- 推理入口仍为 ModelBridge 43821，换成本机推理密钥后转发原始请求/响应；不重新解释工具、改模型或重放请求。保留旧 WorkBuddy 路径作为透明别名。错误状态、流内容、取消和背压均保留；引擎无法连接返回 502，不能笼统报 400。
- 两个入口都由 CLIProxyAPI 自身处理参数兼容；原有严格入口/专用转换策略退出运行路径。界面明确展示该变化，不能继续宣称无损、关闭推理或严格 1 token。
- 采用 React + Ant Design；操作逻辑参考官方管理中心，复用适合的 MIT 代码并保留来源。设置密钥仅首次输入，不回显到状态接口。账号展示只取安全字段，不返回管理接口里的 id_token、路径和凭据对象。
- 旧适配器及测试保留为历史回归材料，运行入口不再使用；旧会员凭据不删除，也不自动回退使用。

## 审查重点

引擎故障不能继续显示健康；第三方管理返回的凭据不能进入 UI；断流不能合成成功结束；账号/引擎更换不能继承旧验证；停止 ModelBridge 不得杀掉外部共享 CLIProxyAPI。
